## Defect Discovered and Fixed

### Registry Defect

**Issue:** Router was incorrectly registered as CallActivity

**Evidence:**
- ComponentRegistry.ts line 117: `bpmnElement: "callActivity"` ❌
- SUPPORTED_COMPONENTS.md line 304: `bpmnElement: "exclusiveGateway"` ✅
- BpmnNode.ts line 26-29: Router example as `"exclusiveGateway"` ✅

**Root Cause:** Placeholder metadata copied from CallActivity pattern

**Fix Applied:**
```typescript
// Before (INCORRECT)
Router: {
    displayName: "Router",
    bpmnElement: "callActivity",  // ❌ WRONG
    activityType: "Router",
    metadata: { ... }              // ❌ Gateways don't use metadata
}

// After (CORRECT)
Router: {
    displayName: "Router",
    bpmnElement: "exclusiveGateway",  // ✅ CORRECT
    // No activityType: Gateways don't use activityType
    // No metadata: Gateways don't use CallActivity metadata
}
```

**Impact:** This was a genuine defect per Engineering Principle #7. Not a refactoring, but a bug fix.

## API Examples

### Basic Router Usage

```typescript
import { Router } from 'sap-integration-sdk';

const router = new Router("Route Orders");

router
  .when("${header.priority} == 'urgent'")
  .to(urgentHandler)
  .when("${header.priority} == 'normal'")
  .to(normalHandler)
  .otherwise()
  .to(defaultHandler);

flow.addComponent(router);
flow.connect(router, urgentHandler);
flow.connect(router, normalHandler);
flow.connect(router, defaultHandler);
```

### Router with Properties

```typescript
const router = new Router("Route by Country", {
    description: "Routes orders based on country code"
});
```

### Fluent API

```typescript
router
  .when("${header.type} == 'A'")
  .to("Component_A")
  .when("${header.type} == 'B'")
  .to("Component_B")
  .otherwise()
  .to("Component_Default");
```
